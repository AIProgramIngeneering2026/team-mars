# Как мы работаем - team-mars

Прямой push в `main` закрыт. Все изменения вносятся через Pull Request (PR). Каждая задача начинается с **Issue**.

## Ветки

Мы используем простой формат: `<тип>/<номер-issue>-<краткое-название>`

**Типы:**
- `feature/` — для новой функциональности или сценариев.
- `fix/` — для исправления ошибок или дополнения документации.
- `docs/` — если задача касается только текста (README, требования).

**Примеры:** `feature/1-timeline-logic`, `fix/3-typo-in-readme`, `docs/5-update-api`.

*Правило: ветка создается от актуального `main`.*

## Коммиты

Соблюдаем стандарт: `<тип>: <что сделано>`
**Типы:** `feat`, `fix`, `docs`, `test`, `chore`.

**Важно:** Описание пишем на русском, в повелительном наклонении, без точки в конце.
```
feat: добавить логику создания Job
docs: обновить критерии приемки для сценария 2
fix: исправить опечатку в описании таймлайна
```

## Pull Request и Review

### Процесс
1. Автор создает PR и связывает его с задачей строкой `Closes #<номер>`.
2. Если работа не закончена, используйте режим **Draft**.
3. Автор назначает ревьюера.

### Ревьюер
Мы не привязываемся жестко к таблице, но стараемся придерживаться распределения «кто кого проверяет» для равномерной нагрузки:

| Кто пишет (Автор) | Кто проверяет (Ревьюер) |
| :--- | :--- |
| СажинАО | БогачевЯК / ЛебедевСИ  |
| БогачевЯК | ЛебедевСИ / ПестеревДЕ |
| ЛебедевСИ | ПестеревДЕ / СажинАО  |
| ПестеревДЕ | СажинАО / БогачевЯК |

**Требования к ревью:**
- Комментарии «ок» или «TEST» не считаются. Пишите, что именно проверили или какой вопрос возник.
- Обсуждение (thread) закрывает тот, кто его начал. После `Approve` автор делает **Squash and merge**.

## Definition of Done (Когда задача готова)

Задача считается выполненной, если:
1. [ ] Выполнены все критерии из Issue или `requirements.md`.
2. [ ] PR влит в `main`.
3. [ ] Соответствующая документация обновлена (README, API или требования).
4. [ ] **Для кода:** Тесты проходят, а новые параметры добавлены в `.env.example`.
