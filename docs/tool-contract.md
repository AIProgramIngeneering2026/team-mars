# Контракт Tool

`Tool.run(transcript) → ToolResult` запускается Dispatcher для выбранного режима.

## 1. Роль Tool в системе

- Tool вызывает только Dispatcher, на этапе `ANALYZING`. Режим из запроса (`operation`) совпадает с ключом, под которым Tool зарегистрирован в Registry: `brief` или `timeline`.
- Tool получает только нормализованные реплики. Он не знает про HTTP, ID ролика, клиента, Job, хранилище и источник субтитров.
- Tool возвращает результат или ошибку. Состояние Job и сохранение результата контролирует Dispatcher.
- Новый алгоритм пересказа добавляется как новый Tool с регистрацией в точке сборки. Dispatcher при этом не меняется.
## 2. Интерфейс

```text
interface Tool {
    run(transcript: Transcript) -> ToolResult        // успех
                                  | ToolError        // отказ по контракту
}

type Transcript      = TranscriptLine[]              // не пустой, startMs не убывает
type TranscriptLine  = { startMs: integer >= 0, text: string }   // text не пуст

type ToolResult = BriefResult | TimelineResult
type BriefResult    = { points: string[] }                              // 1+ непустых строк
type TimelineResult = { segments: { startMs: integer >= 0,
                                    points: string[] }[] }              // 1+ отрезков, в каждом 1+ тезисов

type ToolError = {
    code: "INVALID_TRANSCRIPT" | "ANALYSIS_FAILED",
    message: string,
    field?: string
}
```
Поле `field` — необязательное. Используется для внутренней диагностики некорректных параметров Tool.

Для ошибок `INVALID_TRANSCRIPT` указывается конкретное поле, например `transcript[0].text` или `transcript[1].startMs`.

Dispatcher записывает подробности ошибки в журнал, но не раскрывает их клиенту. Публичная ошибка остаётся `ANALYSIS_FAILED` согласно контракту.

Данные отдельного запуска передаются только аргументом `run(transcript)`. Режим, ID ролика и настройки в `run` не передаются. Настройки Tool получает при создании в точке сборки.

## 3. Вход

| Правило | Подробности |
|---|---|
| Список не пуст | Минимум одна реплика |
| `startMs` | Целое число не меньше 0, миллисекунды от начала ролика |
| Порядок | `startMs` не убывает. Реплики с равным `startMs` сохраняют исходный порядок |
| `text` | Строка, в которой есть хотя бы один непробельный символ |
| Размер | Отдельного предела у Tool нет. Предел задаёт адаптер: до 2 МиБ после распаковки, иначе Job получает `TRANSCRIPT_TOO_LARGE` и Tool не запускается |
| Неизменяемость | Tool не изменяет переданный список и объекты в нём |

Нарушение любого правила — `INVALID_TRANSCRIPT`. Для корректной работы системы такой вход невозможен, потому что реплики уже проверил адаптер. Проверка в Tool защищает его границу от ошибок в соседних компонентах и от повторного использования Tool вне Dispatcher.

## 4. Результат

Общие правила:

- Результат — новый объект. Он не ссылается на изменяемые структуры входа.
- Каждый тезис — непустая строка. Пустых списков тезисов и пустых списков отрезков не бывает.
- Форма результата соответствует режиму. Для `brief` это `BriefResult`, для `timeline` — `TimelineResult`.
- Результат не содержит служебных полей и данных, которых нет в схеме OpenAPI (`BriefResult`, `TimelineResult`).
Правила для `TimelineResult`:

- `startMs` каждого отрезка равен `startMs` одной из реплик входа. Таймкоды не вычисляются заново.
- Отрезки идут в порядке возрастания `startMs`. Значения не повторяются.
## 5. Ошибки

| Код | Кто возвращает | Когда | Итог для Job | Что видит клиент |
|---|---|---|---|---|
| `INVALID_TRANSCRIPT` | Tool | Вход нарушает правила раздела 3 | `FAILED / ANALYSIS_FAILED` | `ANALYSIS_FAILED` |
| `ANALYSIS_FAILED` | Tool | Вход корректен, но результат построить не удалось | `FAILED / ANALYSIS_FAILED` | `ANALYSIS_FAILED` |
| Неожиданное исключение | Dispatcher | Tool завершился исключением, а не `ToolError` | `FAILED / ANALYSIS_FAILED` | `ANALYSIS_FAILED` |
| Результат неверной формы | Job по запросу Dispatcher | Форма не соответствует режиму, список тезисов или отрезков пуст, `startMs` нарушает правила раздела 4 | `FAILED / ANALYSIS_FAILED` | `ANALYSIS_FAILED` |
| Tool не найден | Dispatcher | В Registry нет Tool под ключом режима. Для корректно собранного приложения невозможно, см. раздел 6 | `FAILED / ANALYSIS_FAILED` | `ANALYSIS_FAILED` |
| `ANALYSIS_TIMEOUT` | Dispatcher, не Tool | Анализ не завершился за 60 секунд с перехода в `ANALYZING` | `FAILED / ANALYSIS_TIMEOUT` | `ANALYSIS_TIMEOUT` |

Правила:

- Клиент видит только публичные коды из `Job` в OpenAPI. Различие `INVALID_TRANSCRIPT` и `ANALYSIS_FAILED` остаётся во внутреннем журнале. Текст `message` из `ToolError` в API не попадает: клиент получает фиксированный текст по коду.
- Tool не возвращает `ANALYSIS_TIMEOUT` и не следит за 60 секундами. Предел обеспечивает Dispatcher. Результат, пришедший после срока, отклоняет хранилище.
- Ошибки Tool не повторяются автоматически. Повторный запуск — новая Job с новым `Idempotency-Key`.
- Tool не завершает Job и не меняет её состояние ни при успехе, ни при ошибке.
## 6. Кто что проверяет

| Что | Кто проверяет | Реакция на нарушение |
|---|---|---|
| Токен клиента | HTTP API | `401 UNAUTHORIZED` |
| Форма тела, `url`, `Idempotency-Key`, значение `operation` из списка режимов | HTTP API | `400`, `413`, `415`, `422` |
| Уникальность пары «клиент — ключ» и конфликт параметров | Реализация хранения | `409 IDEMPOTENCY_CONFLICT` или исходный ответ |
| Нормализация ID ролика | Прикладной сценарий | `422 INVALID_FIELD` с полем `url` |
| Права клиента на Job | Прикладной сценарий | `404 JOB_NOT_FOUND` при чтении или отмене чужой либо отсутствующей Job |
| Ответ источника субтитров: схема, размер, таймкоды, порядок | Адаптер субтитров | `TRANSCRIPT_INVALID_RESPONSE`, `TRANSCRIPT_TOO_LARGE` |
| Режим → Tool | Registry (поиск) и Dispatcher (реакция на отсутствие) | `FAILED / ANALYSIS_FAILED` |
| Согласованность списка режимов, регистраций и OpenAPI | Точка сборки при запуске: каждое значение `operation` из OpenAPI зарегистрировано один раз, иначе приложение не стартует | Ошибка запуска |
| Транскрипт на входе `run` | Tool (защита своей границы) | `INVALID_TRANSCRIPT` |
| Результат Tool: форма, непустота, порядок | Tool соблюдает, Job проверяет перед `COMPLETED` | `FAILED / ANALYSIS_FAILED` |
| Допустимость перехода, исходное состояние, версия, право обработки, срок анализа | Job и реализация хранения | Запись отклоняется, статус сохраняется |

## 7. Требования к реализации

- **Без состояния между запусками.** Registry хранит готовые объекты, поэтому один экземпляр Tool может вызываться для разных Job. Результаты одного запуска не должны влиять на другой.
- **Безопасность при параллельных вызовах.** Несколько Job могут выполнять `run` одновременно в одном экземпляре Tool.
- **Без побочных эффектов.** Tool не пишет в хранилище, не меняет Job и не вызывает Dispatcher.
- **Без внешних обращений в первой версии.** Тезисы извлекаются из реплик простыми правилами. Если позже внутрь Tool будет подключена модель, контракт сохраняется: сбой модели превращается в `ANALYSIS_FAILED`, а общий предел 60 секунд по-прежнему обеспечивает Dispatcher.
- **Отмена.** Tool не получает сигнала отмены. После отмены Job его результат отбрасывается: хранилище отклоняет запись.
- **Текст из ролика — недоверенные данные.** Tool не интерпретирует реплики как команды и не включает в результат ничего, кроме тезисов, построенных из текста реплик.
## 8. Tool

### 8.1. BriefSummaryTool

| | |
|---|---|
| Ключ в Registry | `brief` |
| Вход | `Transcript` по разделу 3 |
| Результат | `BriefResult` — `{points: string[]}`, не меньше одного тезиса |
| Ошибки | `INVALID_TRANSCRIPT`, `ANALYSIS_FAILED` |
| Скрывает | Алгоритм выделения тезисов |

Пример успеха:

```json
// вход
[ {"startMs": 0,     "text": "Сегодня разберём, как работает кэш."},
  {"startMs": 4200,  "text": "Сначала про кэш процессора."},
  {"startMs": 61000, "text": "Теперь про кэш браузера."} ]

// результат
{ "points": ["Как работает кэш", "Кэш процессора", "Кэш браузера"] }
```

Примеры отказов:

| Вход | Ошибка |
|---|---|
| `[]` | `INVALID_TRANSCRIPT` |
| `[{"startMs": 100, "text": "a"}, {"startMs": 50, "text": "b"}]` — время убывает | `INVALID_TRANSCRIPT` |
| `[{"startMs": 0, "text": "   "}]` — текст из пробелов | `INVALID_TRANSCRIPT` |
| Корректный вход, но тезисы не выделены | `ANALYSIS_FAILED` |

### 8.2. TimelineDigestTool

| | |
|---|---|
| Ключ в Registry | `timeline` |
| Вход | `Transcript` по разделу 3 |
| Результат | `TimelineResult` — `{segments: {startMs, points}[]}`, не меньше одного отрезка, `startMs` берётся из реплик, порядок по возрастанию |
| Ошибки | `INVALID_TRANSCRIPT`, `ANALYSIS_FAILED` |
| Скрывает | Алгоритм группировки реплик и построения таймлайна |

Пример успеха, тот же вход:

```json
{ "segments": [
    { "startMs": 0,     "points": ["Как работает кэш", "Кэш процессора"] },
    { "startMs": 61000, "points": ["Кэш браузера"] } ] }
```

Примеры отказов:

| Вход или ситуация | Ошибка |
|---|---|
| `[{"startMs": -1, "text": "a"}]` | `INVALID_TRANSCRIPT` |
| Корректный вход, но группировка не построена | `ANALYSIS_FAILED` |
| Результат с `startMs`, которого нет во входе | Job отклоняет результат: `FAILED / ANALYSIS_FAILED` |
