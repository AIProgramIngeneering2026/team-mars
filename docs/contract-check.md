# Проверка контракта колодой

| Карта | Ответ контракта |
|---|---|
| К1 Двойной клик | Два одинаковых POST с одним ключом через 100 мс возвращают `202` и один ID. Создаётся одна Job. [Создание Job](api-contract.md#создание-job) |
| К2 Ответ потерялся | Повтор после сетевого таймаута с тем же ключом возвращает исходные ID и `Location`. Клиент читает текущий статус по `Location`. [Создание Job](api-contract.md#создание-job) |
| К3 Неизвестная операция | `operation: "translate"` даёт `422 UNSUPPORTED_OPERATION` с полем `operation`. Job не создаётся. [Ошибки запроса](api-contract.md#ошибки-запроса) |
| К4 Кривые параметры | Запрос без `url` даёт `422 INVALID_FIELD` с полем `url`. Job не создаётся. [Ошибки запроса](api-contract.md#ошибки-запроса) |
| К5 Воскрешение | Повтор после `COMPLETED` или `FAILED` со старым ключом возвращает прежний ID. Новый ключ создаёт `CREATED` Job с другим ID. Старый результат сохраняется. [Создание Job](api-contract.md#создание-job) |
| К6 Отмена | Отмена во время анализа даёт `200` и `CANCELLED`. Запоздавший результат Tool отбрасывается. [Чтение и отмена](api-contract.md#чтение-и-отмена) |
| К7 Огромный вход | Тело в 1 МиБ даёт `413 REQUEST_TOO_LARGE` без Job. Субтитры в 3 МиБ переводят Job в `FAILED / TRANSCRIPT_TOO_LARGE`. [Ошибки запроса](api-contract.md#ошибки-запроса) · [Состояния и сбои](api-contract.md#состояния-и-сбои) |
| К8 Чужой или несуществующий ID | Чтение и отмена дают одинаковые `404 JOB_NOT_FOUND` и тело. [Чтение и отмена](api-contract.md#чтение-и-отмена) |
| К9 Перезапуск сервера | После остановки Dispatcher в `ANALYZING` проверка просроченного права переводит Job в `FAILED / PROCESSING_INTERRUPTED`. [Состояния и сбои](api-contract.md#состояния-и-сбои) |
| К10 Внешний сервис | При молчании источника 30 секунд Job получает `FAILED / TRANSCRIPT_TIMEOUT` после двух попыток. Ответ без таймкодов даёт `FAILED / TRANSCRIPT_INVALID_RESPONSE`. [Состояния и сбои](api-contract.md#состояния-и-сбои) |

## Что предложил ИИ

Промпт для разбора исходной версии контракта и колоды К1–К10:

> Сыграй атакующего. Прочитай контракт API пересказа YouTube-роликов и колоду К1–К10. Найди ровно три ситуации, для которых контракт не определяет наблюдаемое поведение. Для каждой дай конкретный запрос или событие, покажи, какого ответа не хватает, и предложи минимальную поправку.

| Находка ИИ | Решение |
|---|---|
| Tool завис, но Dispatcher продолжает продлевать право обработки. Клиент может бесконечно видеть `ANALYZING`. | Приняли. Ввели предел анализа в 60 секунд и `ANALYSIS_TIMEOUT`. [Состояния и сбои](api-contract.md#состояния-и-сбои) |
| В `watch?v=abcdefghijk&v=lmnopqrstuv` два ID. Из контракта неясно, какой использует адаптер и ключ идемпотентности. | Приняли. Требуем ровно один `v`, иначе `422 INVALID_FIELD` с полем `url`. [Создание Job](api-contract.md#создание-job) |
| Кэш клиента может выдать ответ со статусом или результатом, полученный до смены учётной записи. | Приняли. Добавили `Cache-Control: no-store` ко всем ответам, включая ошибки. [Чтение и отмена](api-contract.md#чтение-и-отмена) |
