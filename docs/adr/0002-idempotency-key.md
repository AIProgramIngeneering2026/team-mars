# ADR-0002. Ключ идемпотентности при создании Job

**Дата** 7 ноября 2026 г.<br>
**Статус** Предложено в рамках практики 2.

## Контекст

Двойной клик или потерянный ответ могут повторить создание. Пользователю при этом нужен способ явно запустить анализ заново.

## Решение

Клиент присылает `Idempotency-Key`. Хранилище атомарно записывает Job и связь ключа с клиентом и параметрами. Повтор с теми же параметрами возвращает прежний ID. Другие параметры с тем же ключом дают `409`. Для явного перезапуска клиент выбирает новый ключ.

## Альтернативы

Создавать Job для каждого запроса проще, но сбой сети даёт дубликаты. Искать дубликаты по ролику и режиму можно без ключа, но тогда трудно отличить повтор после сбоя от нового запуска.

## Цена и пересмотр

Клиент сохраняет ключ между попытками, а хранилище обеспечивает уникальность пары клиент–ключ. Пересмотрим срок хранения ключей вместе с политикой удаления Job, если накопление истории станет существенным.
