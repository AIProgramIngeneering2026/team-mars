# ADR-0004. Повторное использование результатов анализа

**Дата:** 15 ноября 2026 г.\
**Статус:** Предложено.

## Контекст

Повторная обработка одного ролика в том же режиме приводит к лишнему
получению субтитров и запуску Tool.

## Решение

Использовать общий кэш результатов для всех клиентов. Поиск выполняется
по `video_id` и `operation`.

При совпадении: - создаётся новая Job с новым ID и владельцем ---
текущим клиентом; - статус устанавливается в `COMPLETED`; - найденный
результат сохраняется в новой Job; - адаптер и Tool не запускаются.

Чужие Job и их ID клиентам не передаются.

Если результата нет, используется обычный путь S1 со статусом `CREATED`.

Проверка `Idempotency-Key` выполняется до поиска результата в кэше.

API возвращает `202 Accepted`, `id`, `status` и `Location`. Результат
доступен через `GET /jobs/{id}`.

## Альтернативы

-   Повторно запускать обработку --- увеличивает нагрузку и время
    ожидания.
-   Возвращать старую Job --- нарушает принцип создания новой Job для
    нового ключа.

## Цена и пересмотр

Необходимо хранить готовые результаты, разделять режимы `brief` и
`timeline` и контролировать доступ к Job по владельцу.

Срок хранения кэша определяется отдельной политикой хранения.

Пересмотрим решение при изменении формата результата, логики анализа или
политики хранения кэша.
