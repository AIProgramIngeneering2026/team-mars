# team-mars
## Пересказ YouTube-роликов по субтитрам

Длинный ролик приходится смотреть целиком, чтобы понять, есть ли в нём нужная информация. Сервис помогает студентам и зрителям обучающих видео быстро понять содержание ролика и найти нужный фрагмент.

### Что входит в первую версию

- Пользователь вставляет ссылку на общедоступный ролик YouTube и выбирает один из двух режимов. По умолчанию включён краткий пересказ.
- **Краткий пересказ** возвращает ключевые тезисы из субтитров.
- **Таймлайн** делит ролик на отрезки и показывает время начала и основные тезисы каждого отрезка.
- Сервис создаёт задачу обработки (Job). По её идентификатору можно посмотреть статус, получить результат или отменить обработку.
- Если субтитры недоступны или источник не отвечает, сервис показывает причину сбоя.

За рамками первой версии остаются скачивание видео, распознавание аудио, поддержка других видеоплатформ и ответы на свободные вопросы о ролике.

### Как устроена обработка

Запрос создаёт `Job` с выбранным режимом. `Dispatcher` получает субтитры через адаптер и выбирает исполнителя в `Registry`. Два исполнителя, `BriefSummaryTool` и `TimelineDigestTool`, работают через общий контракт `Tool` и возвращают `ToolResult`. Для тестов адаптер отдаёт заранее подготовленные субтитры с таймкодами.

Поставщика субтитров предстоит выбрать. Для первой версии тезисы можно извлекать из самих субтитров простыми правилами. Модель можно подключить позже внутри исполнителя, сохранив контракт `Tool`.

### Черновая реализация S1 и S5

Для обсуждения командой используется Python 3.9+ со стандартной библиотекой, SQLite и один фоновый исполнитель. Это локальный прототип с подготовленными субтитрами. Демонстрационный ID `abcdefghijk` относится к файлу тестовых данных, реальный YouTube сервис пока не запрашивает.

Запуск из корня репозитория:

```sh
source .env.example
python3 -m mars
```

В другом терминале создать Job:

```sh
curl -i http://127.0.0.1:8000/jobs \
  -H 'Authorization: Bearer local-demo-token' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: first-brief' \
  -d '{"url":"https://youtu.be/abcdefghijk","operation":"brief"}'
```

В ответе будет ID и `Location`. Прочитать результат после фоновой обработки:

```sh
curl http://127.0.0.1:8000/jobs/ID_ИЗ_ОТВЕТА \
  -H 'Authorization: Bearer local-demo-token'
```

Повторить создание с новым ключом и полной ссылкой на тот же ролик:

```sh
curl -i http://127.0.0.1:8000/jobs \
  -H 'Authorization: Bearer local-demo-token' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: cached-brief' \
  -d '{"url":"https://www.youtube.com/watch?v=abcdefghijk&t=30s","operation":"brief"}'
```

После завершения первой Job второй запрос получит новую Job в `COMPLETED` с кодом `200`. Данные результата копируются в новую Job в одной транзакции. Повтор с прежним ключом возвращает первоначальный ответ и ID, даже если обработка уже завершилась. Режим `timeline` имеет отдельные результаты. Для проверки таймлайна замените режим и используйте новый ключ.

Проверки:

```sh
python3 -m unittest discover -s tests -v
```

Решения для ревью команды:

- `operation` используется как название режима, в том числе при поиске кэша.
- При попадании в кэш выбран `200` с ID, `COMPLETED` и `Location`. Выдача результата идёт через GET. Этот вариант требуется согласовать с OpenAPI в задаче #13.
- Поддерживаются HTTPS-ссылки с доменами `youtube.com`, `www.youtube.com` и `youtu.be`. Ключ кэша включает клиента, ID ролика и режим.
- Запуск поддерживает один заданный через окружение токен. Для нескольких пользователей требуется согласовать аутентификацию. Сырой токен в БД не сохраняется.
- Кэш пока хранится без срока истечения. Одновременные новые запросы с разными ключами до появления готового результата создают отдельные Job.
- Исполнители извлекают первые уникальные предложения, таймлайн группирует реплики по минутам. Качество пересказа предстоит оценить на реальных субтитрах.
- SQLite хранит задания между запусками. Просроченные задания в работе получают `PROCESSING_INTERRUPTED`. Проверка времени анализа и продление права выполняются отдельным потоком.
- Если Tool зависнет внутри вызова, Job получит `ANALYSIS_TIMEOUT`, но единственный исполнитель сможет взять следующую Job после возврата из этого вызова или перезапуска процесса. Для изоляции зависших операций требуется отдельное решение команды.
- Адаптер реального источника, сетевые повторы S3, Docker Compose и производственный HTTP-сервер остаются для дальнейшей реализации.
